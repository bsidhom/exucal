# The costliest expressions

Status: the catalogue of stage 8 (docs/calculator-plan.md, task 8.3,
under D25). It lists the costliest inputs the cost search has found,
what each pays for, and the issue that would make it cheaper. Runs of
the search add to it over time; the table below is regenerated by each
run, and the prose around it is revised by hand when a run changes the
picture.

The catalogue is the target for two kinds of work. Making the kernels
cheaper takes a case off the list or moves it down; keeping the
interface responsive whatever an evaluation costs (#118, with #119 to
#121) is measured against the same cases, since they are the ones that
freeze it today. Neither is part of the plan: the plan finds and records
the costs, and the issues named below carry the work.

## How a case is measured

A case is a `have` text, a `want` text and the settings panel's
settings. The harness (bench/stress/harness.ts) measures what the
converter runs on each keystroke, `outcomeOf`, in wall time:

- **Cold** is the first evaluation in a worker of its own, whose memos
  are empty but whose unit table is built, as the app builds it at
  startup. It pays for what is computed once: the constants at a new
  ceiling, the Bernoulli run the Gamma family's series take.
- **Warm** is the same case evaluated again in that worker. It pays for
  every pass alone, and is what a keystroke costs once a session has
  seen the case.
- **Passes** is how many passes of the retry loop the warm evaluation
  ran. Every case here runs the whole schedule to the ceiling, since
  its value never certifies: nine passes at the default settings, eleven
  at the highest cap the default range limit allows.
- **Typing** is the case typed out a keystroke at a time, `outcomeOf` on
  every prefix of the `have` in order, in one worker so that the memos
  carry over as they do in a session. The slowest keystroke is usually
  the last, the one that completes the expression; a prefix that never
  certifies costs as much as the whole.

The catalogue ranks the cases by their warm cost per costly call, so
that an expression of many calls does not outrank the call that makes
it costly. Only cases whose warm cost reaches a second are kept, so that
an entry stays among the costliest when measured again: on one machine
the noise is milliseconds. The timings are those of the machine the
search ran on, which each entry in bench/stress/catalogue.json names;
on another machine only their ratios compare, which is what the stress
suite reports.

## Reproducing a case

Each entry in bench/stress/catalogue.json records where it came from:
the seed and index that drew it, or its place in the fixed enumeration.
`pnpm stress:search --seed <seed> --cases <n>` replays a run, and
`--list` prints the cases a seed draws without evaluating them. Typing
the `have` into the converter, with the entry's settings, reproduces the
cost a user meets. `pnpm stress` measures every entry again, and fails
only if one gives a different value or passes its deadline.
